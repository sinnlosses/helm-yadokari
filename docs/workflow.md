# 進捗管理とHandoffの詳細

`CLAUDE.md`の「進捗管理とHandoff」節で触れている `tasks.json` / `progress.md` のフィールド定義。
運用ルール自体（毎セッション最初に読む、完了の判定基準など）は `CLAUDE.md` 側の短い手順を参照。

## tasks.json のフィールド

各タスクは以下のフィールドを持つオブジェクト:

| フィールド     | 内容                                                           |
| -------------- | -------------------------------------------------------------- |
| `id`           | `T-001` のような通し番号                                       |
| `task`         | タスクの内容（背景・理由が分かるように具体的に書く）           |
| `status`       | `todo` / `doing` / `done`                                      |
| `passes`       | 完了条件を満たしたか（`boolean`）                              |
| `evidence`     | 完了の証拠（コミットハッシュ、テスト件数、生成物へのパスなど） |
| `dependencies` | 先に完了している必要がある他タスクの `id` 配列                 |

## progress.md の構成

以下の4セクションで構成する:

- **完了したこと**: 何を、なぜ、どう検証したか（コミットハッシュ・テスト件数を添える）
- **次にやること**: 未着手タスクの一覧（`tasks.json`の`id`を添える）
- **未解決**: 判断が必要で保留中の事項
- **注意**: 誤解しやすい前提・外部リソースの状態など、次回セッションで踏み外しやすい点

## 良いevidenceの書き方

「完了しました」という宣言だけでは合格にしない。次のような、後から検証可能な形で残す:

- コミットハッシュ（`commit e59c410` のように）
- `pnpm check` の通過件数（テスト件数が変わっていれば増減が分かる）
- 生成物や検証ログへの具体的な参照
