ドキュメントの現在の姿を7つの検査にかけ、出た指摘を直す。**変更差分ではなく現状**を見るので、
`git diff` を起点にする `/code-review` とは対象が重ならない。

判断基準そのものはここに書かない。指摘を直すか残すかは
[`docs/coding-standards.md`](../../../docs/coding-standards.md)「コメント」の
**「今の挙動を説明しているか、昔の話か」の1問**で決める（あの節は同じ判定を
「機械化しない」と明記している。この検査も候補を挙げるところまでで止める）。正典の寄せ先は
同じ節の対応表、構成の規約は [`docs/architecture.md`](../../../docs/architecture.md) が正典。

## 対象

`docs/*.md`（`docs/requirements-grilling.md` を除く）と `README.md`・`CLAUDE.md` の8ファイル。

- **`docs/history/` 配下は対象外。** 当時の記述をそのまま残す規約があるため、整備しない
  （`test-inventory.md` も `history/` 配下なので対象外）
- **`docs/requirements-grilling.md` も対象外。** 要件検討時のQ&Aログで、`history/` と同じく
  当時の記述をそのまま残すもの
- 検査1（通読ガード）だけは `docs/*.md` のみを見る。`README.md` と `CLAUDE.md` は
  **通読される前提の入口**なので「通読しない」宣言がそぐわない

## 検査項目

指摘を2群に分ける。**確定群は直せば必ず正しくなる**もの、**候補群は上の1問で正否が決まる**もの。

| #   | 何を見るか                                     | 何をもって指摘とするか                                                   | 群   |
| --- | ---------------------------------------------- | ------------------------------------------------------------------------ | ---- |
| 1   | 通読ガード                                     | 20KB以上の `docs/*.md` に「通読しない」と「索引」の両方が無い            | 確定 |
| 2   | タスク番号の混入                               | `T-` + 3桁がある。**ただしコミットメッセージの説明は対象外**             | 確定 |
| 3   | 相対リンク切れ                                 | `](./x.md)` の指す先が存在しない                                         | 確定 |
| 4   | 索引 → 本文                                    | 索引エントリを `sed` パターンにして節を切り出すと空になる                | 確定 |
| 5   | 本文 → 索引                                    | 本文の見出しが索引ブロックのどこにも現れない                             | 候補 |
| 6   | 実在しない識別子・パス                         | `` `foo()` `` が `src`/`scripts`/`test` に無い、`` `src/x.ts` `` が無い  | 候補 |
| 7   | 見出しタイトルの重複                           | 同じ見出しが2ファイル以上にある（読み方のボイラープレートを除く）        | 候補 |

検査5〜7が候補群なのは、**そのままで正しい場合があるから**:

- 検査6は「以前あって廃止した」という**経緯の記録**なら正当（正典は経緯を書く場所）。
  今の姿の説明として書かれているなら実物とのズレ
- 検査7は片方が参照でもう片方が本文なら正当。**両方が本文なら正典の二重化**
- 検査5は索引に足すか、まとめの見出しとして索引に載せないかの判断が要る。
  **見落としが起きる形が1つある**: 見出し名が索引の「中身」列の語の一部になっていると
  一致してしまい、索引に無くても指摘に出ない。グループ見出しを疑うときは
  `grep -E '^#{2,4} ' <file>` と索引を目視で突き合わせる

## 検査コマンド

`sh` で実行する（`zsh` は変数の単語分割をしないため `$(targets)` の形が動かない）。BSD `sed` は
`\|` の交替を解釈しないので `sed -n -E` を使っている。リポジトリのルートで実行する。

```sh
sh <<'EOS'
targets() { for f in docs/*.md README.md CLAUDE.md; do case "$f" in *requirements-grilling.md) continue;; esac; echo "$f"; done; }
indexed() { echo docs/architecture.md docs/coding-standards.md docs/glossary.md docs/requirements.md; }

echo "== 検査1 通読ガード =="
for f in $(targets); do
  case "$f" in README.md|CLAUDE.md) continue;; esac
  s=$(wc -c < "$f"); [ "$s" -ge 20480 ] || continue
  grep -q '通読しない' "$f" && grep -q '索引' "$f" || echo "  NG $f (${s}B)"
done

echo "== 検査2 タスク番号の混入 =="
grep -nH -E 'T-[0-9]{3}' $(targets) || true

echo "== 検査3 相対リンク切れ =="
for f in $(targets); do d=$(dirname "$f")
  for p in $(grep -oE '\]\(\.{1,2}/[^)#]+' "$f" | sed 's/^](//'); do
    [ -e "$d/$p" ] || echo "  NG $f -> $p"
  done
done

echo "== 検査4 索引 → 本文 =="
for f in $(indexed); do
  grep -oE '^\| *#{2,4} [^|]+' "$f" | sed 's/^| *//; s/ *$//' | sort -u | while IFS= read -r h; do
    pat=$(printf '%s' "$h" | sed 's/[][\.*^$/]/\\&/g')
    [ "$(sed -n "/^$pat/,/^#\{2,4\} /p" "$f" | wc -l)" -gt 1 ] || echo "  NG $f 切り出せない索引エントリ: [$h]"
  done
done

echo "== 検査5 本文 → 索引 =="
for f in $(indexed); do
  idx=$(sed -n -E '/^### (節|用語)の索引/,/^## /p' "$f")
  grep -E '^#{2,4} ' "$f" | sed 's/^#\{2,4\} //' | while IFS= read -r t; do
    case "$t" in このドキュメントの読み方|このファイルの読み方|節の索引|用語の索引|このファイルは通読しない) continue;; esac
    key=$(printf '%s' "$t" | sed 's/\\\[/[/g; s/\\\]/]/g; s/ \/ .*//; s/ — .*//; s/。.*//')
    printf '%s' "$idx" | grep -qF -- "$key" || echo "  ? $f 索引に無い見出し: [$t]"
  done
done

echo "== 検査6 実在しない識別子・パス =="
for f in $(targets); do
  grep -oE '`[a-zA-Z_][a-zA-Z0-9_]*\(\)`' "$f" | tr -d '`()' | sort -u | while read -r fn; do
    grep -rqE "\b${fn}\b" src scripts test 2>/dev/null || echo "  ? $f 実在しない関数: ${fn}()"
  done
  grep -oE '`(src|scripts|test|docs)/[A-Za-z0-9_./-]+\.(ts|md|yaml|yml|json)`' "$f" | tr -d '`' | sort -u | while read -r p; do
    [ -e "$p" ] || echo "  ? $f 実在しないパス: $p"
  done
done

echo "== 検査7 見出しタイトルの重複 =="
for f in $(targets); do grep -E '^#{2,4} ' "$f" | sed "s|^#\{2,4\} |$f	|"; done \
 | grep -vE '	(このドキュメントの読み方|このファイルの読み方|このファイルは通読しない|節の索引|用語の索引)$' \
 | sort -t'	' -k2 | awk -F'	' 'NR>1&&$2==p{print "  ? 重複見出し ["$2"]: "q", "$1}{p=$2;q=$1}'
EOS
```

## 手順

1. **検査を走らせる**。下の「検査コマンド」をそのまま実行する。


   検査6のパス検査は `config/` で始まるパスを見ない。`docs/architecture.md` の責務表が
   `src/lib/` からの相対で `config/schema.ts` のように書いており、誤検知しかしないため。

2. **仕分ける**。確定群（検査1〜4）と候補群（検査5〜7）に分け、検査番号・ファイル・件数の
   一覧を出す。検査2は `docs/coding-standards.md`「タスク番号を書かない」が
   **コミットメッセージを対象外**としているので、その説明のための記述は指摘から外す。

3. **直す範囲を決める**。
   - **ユーザーがいるセッション**: 一覧を提示して選んでもらう。候補群は
     「今の挙動か昔の話か」をユーザーと確認してから直す
   - **`/loop` や委譲で動いていてユーザーがいないとき**: **確定群だけを直す。**
     候補群は直さず、報告に載せる。正典の寄せ先を無承認で変えないため

4. **直す**。候補群で「本文が二重にある」と判明したものは、**正典側を残して他方を参照に置き換える**
   （両方を消さない・両方を残さない）。正典の側を書き換えたときは、**同じファイル内の索引・表・
   型名まで `grep` で洗う**（索引だけ古いまま残るのが最も起きやすい）。

5. **検査をもう一度走らせる**。直した指摘が消え、**新しい指摘が増えていない**ことを確認する。

6. **`pnpm check` を通す**。ドキュメントだけの変更でも省略しない。

7. **コミットする**。1回の実行＝1コミット。件名の書式は
   [`docs/workflow.md`](../../../docs/workflow.md)「コミットメッセージ」に従う
   （このスキル自体はタスクIDを持たないので、タスク由来でなければ件名にIDを付けない）。

8. **push はしない**。外部への反映は明示的に頼まれたときだけ行う。

## 完了報告のフォーマット

最後に必ず次を示す:

- **検査番号ごとの指摘件数**（実行前 → 実行後）。0件だった検査も0と書く
- 直した指摘と、直さずに残した指摘。**残したものは「昔の話として正当」なのか
  「承認待ち」なのかを区別する**
- 正典を寄せ替えたなら、どちらを正典にしてどちらを参照にしたか
- `pnpm check` の結果（ファイル数・テスト件数）
