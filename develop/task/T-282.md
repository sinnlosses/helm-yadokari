## 目的・背景
`src/lib/platform/adapter.ts` の `PlatformAdapter.createMergeRequest` の戻り値は `Promise<void>` で、作った MR（GitHub では PR）の
URL を捨てている。そのため、CREATED になった設定ユニットのログ（`src/steps/apply-updates/` の CREATED を出す箇所）にも、
レポートの表（`src/lib/report/format-report.ts`）にも MR へのリンクが無く、その回の実行で何ができたかを結果から辿れない。

## 決まっていること（蒸し返さない）
- GitLab・GitHub の両方で URL を返す（API の応答の web URL を使い、自前で組み立てない）
- dry-run では MR を作らないので URL は無い

## 解くべき論点
なし

## やること
前提の確認結果: 目的・背景の記述（`Promise<void>`、CREATED のログ箇所 `apply-updates.ts`、`format-report.ts`）は実物と一致。誤りなし。dry-run は `build-plans.ts` の `buildPlan()` が SKIPPED(dry_run) で打ち切り `applyUpdates()` に到達しないので、URL 無しは型上 CREATED 変種にだけ URL を持たせれば自然に満たされる（dry-run 側の変更は不要）。

設計: URL は `ConfigUnitUpdateOutcome` の CREATED 変種にだけ `readonly mergeRequestUrl: PlatformUrl` として足す（SKIPPED/ERROR に無理に足さない）。`ConfigUnitReport` は `ConfigUnitUpdateOutcome & {...}` なので自動で伝わり、`toConfigUnitReport()` の `...outcome` もそのまま通る。
