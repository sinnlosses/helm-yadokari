## 目的・背景
`docs/requirements.md` は「旧タグが未設定（初回反映など）の場合は比較のしようがないため、その旨を記載し比較URLは省略する」
（MR 本文の節）としている。実装の `src/steps/apply-updates/sub-steps/build-mr-content.ts` は旧タグのリンクと比較 URL を常に組み立てる。
さらに `src/lib/helm.ts` の `lookupValueAtAnchor` は `String(node.value)` で値を取るので、アンカーの値が null（`tag: &a`）だと
`"null"` という文字列になり、`null` をタグ名にしたリンクと比較 URL が MR に載る。

## 決まっていること（蒸し返さない）
- 実装を要件に合わせる（ユーザーが 2026-09-30 に選択。要件の文言は変えない）
- 「旧タグが未設定」はアンカーの値が null または空文字のとき

## 解くべき論点
なし

## やること

### 調べた結果（前提の確認）
- 背景の主張は実物と合っている: `build-mr-content.ts` の `buildImageTagSection` は旧タグのリンクと `buildCompareUrl` を常に出す。`helm.ts` の `lookupValueAtAnchor` は `String(lookup.node.value)` で、null は `"null"` になる。空文字は `""` のまま。
- `lookupValueAtAnchor`・`getRequiredValueAtAnchor` の利用箇所は全部で次の4つ。
  - `stage-image-tag-updates.ts`（`getRequiredValueAtAnchor` → `toTagName`）。現在値が `"null"` だと最新タグと不一致になり更新対象になる。`""` も同じ。`trackedHeadTagNames.has` は不一致。値の書き込みは T-280 で対応済みで壊れない。結果は `updates[].currentTag = "null"` または `""`。
  - `stage-helm-branch-ref-updates.ts`（`getRequiredValueAtAnchor` → `toBranchName`）。現在値が null だと `"null"` という文字列のブランチ名を `currentBranch` に積み、MR の「旧ブランチ」列とログに `null` と出る。同じ読み取りなので同じ扱いにする。
  - `scripts/lint/remote-existence/remote-existence.ts` L269。`kind` しか見ず値は使わない。null のアンカーは scalar のままなので挙動は変わらない。変更不要。
  - `test/lib/helm.test.ts`（単体テスト）。
- 旧タグが流れる先は次のとおり。`ImageTagUpdate.currentTag`（`src/domain/types.ts`）→ `collect-mr-entries.ts`（`update` をそのまま渡すだけ）→ `build-mr-content.ts`（リンクと比較 URL）、`describe-plan.ts` の `describePlan`（`PlanLogSummary.updates[].currentTag`）→ `build-plans.ts`・`apply-updates.ts` のログ出力（dryRun 含む）。レポート（`src/lib/report`）と `format-report` は旧タグを持たないので影響なし。
- 判定の分岐: 更新要否は `currentTagName === latestTagName || trackedHeadTagNames.has(currentTagName)` のみ。未設定のときは常に更新対象にする（最新タグは空にならないので現状の比較の結果と同じ。ただし `"null"` を経由しないようにする）。

### 方針
「未設定」は型で表す（`| undefined`、`?:` は使わない）。`lookupValueAtAnchor` は null を `""` に寄せて返し（`AnchorValueLookup` の scalar は string のまま。null・空文字を区別しない）、未設定の判定は呼び出し側で `=== ""` とする。

### 変更内容
1. `src/lib/helm.ts`
   - `lookupValueAtAnchor`: `lookup.node.value === null ? "" : String(lookup.node.value)`。`/** */` に「アンカーの値が null（`&a` だけ・`~`・`null`）のときは空文字を返す」を追記。`getRequiredValueAtAnchor` の戻り値の説明にも同じことを1行。`String(null)` に頼った箇所は他に無い。
2. `src/domain/types.ts`
   - `ImageTagUpdate.currentTag` を `TagName | undefined` に。コメントに「values.yaml の値が null・空文字のとき undefined」を追記。
   - `HelmBranchRefUpdate.currentBranch` を `BranchName | undefined` に（同上）。
3. `src/steps/build-plans/sub-steps/stage-image-tag-updates.ts`（`stageImageTagUpdate`）
   - `getRequiredValueAtAnchor` の結果 `raw` を受け、`const currentTagName = raw === "" ? undefined : toTagName(raw)`。
   - スキップ判定は `currentTagName !== undefined && (currentTagName === latestTagName || trackedHeadTagNames.has(currentTagName))`。未設定なら常に更新して `updates` に `currentTag: currentTagName`（undefined）を積む。
4. `src/steps/build-plans/sub-steps/stage-helm-branch-ref-updates.ts`（`stageHelmBranchRefUpdate`）
   - `currentBranchRaw === branchRef` の判定はそのまま（`""` は一致しないので更新対象になる）。`currentBranch: currentBranchRaw === "" ? undefined : toBranchName(currentBranchRaw)`。
5. `src/steps/shared/describe-plan.ts`
   - `PlanLogSummary.updates[].currentTag` を `TagName | undefined`、`HelmBranchRefLogSummary.currentBranch` を `BranchName | undefined` に。値は `update` から素通しでよい（ログには undefined のキーが出ない＝旧値なしの意味になる）。
6. `src/steps/apply-updates/sub-steps/build-mr-content.ts`
   - `buildImageTagSection`: `update.currentTag === undefined` のとき、旧タグ列は `未設定`、比較列は `-`（値が無いセルは `-` で埋める既存方針に合わせ、比較 URL は出さない）。それ以外は現状どおり。関数の `/** */` に「旧タグが未設定の行は…」を追記。新タグ列とパイプライン列は変えない。
   - `buildHelmBranchRefSection`: `update.currentBranch === undefined` のとき旧ブランチ列は `未設定`（バッククォートなし）。
   - 要件の文言は変えない（「その旨を記載し比較 URL は省略」を満たす）。

### 完了条件との対応
- 旧タグ null・空文字で MR 本文に旧タグのリンク・比較 URL が無く「未設定」が出る: `test/steps/apply-updates/sub-steps/build-mr-content.test.ts` に、`currentTag: undefined` の行で「旧タグ列が `未設定`、`compare` を含まない・`[undefined]` を含まない・比較セルが `-`」を確かめるテストを追加。helm 側も `currentBranch: undefined` の行のテストを追加。
- `"null"` を文字列として扱わない（更新要否・ログを含む）:
  - `test/lib/helm.test.ts`: `variables:\n  - &b\n`、`- &b ~`、`- &b null`、`- &b ""` がいずれも `{ kind: "scalar", value: "" }` になるテスト。`- &b "null"`（引用符つき文字列）は `"null"` のままのテストも1件。
  - `test/steps/build-plans/sub-steps/stage-image-tag-updates.test.ts`: 値が null（`- &appVersion\n`）と `""` のとき更新対象になり `updates[0].currentTag` が undefined（`"null"` でない）で、書き換え後の values.yaml が最新タグを持つことを確認するテスト。
  - `test/steps/build-plans/sub-steps/stage-helm-branch-ref-updates.test.ts`: 向き先ブランチの値が null のとき `currentBranch` が undefined で、書き込みが `branchRef` になるテスト。
