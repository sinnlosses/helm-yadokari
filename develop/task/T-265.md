## 目的・背景
このCLI自体の依存更新が止まっている。`.gitlab-ci.yml` の `renovate` ジョブは `image: renovate/renovate:latest` で固定されておらず、実行のたびに中身が変わりうる。また `.renovaterc.json` の `packageRules`（`groupName: "runtime dependencies"`）が `js-yaml` を挙げているが、実際の依存は `yaml`（`package.json`）で、`@octokit/rest` も抜けている。

## 決まっていること（蒸し返さない）
- pipeline schedule の作成（GitLab 側の設定）はこのタスクでは行わない
- GitHub 対応（`PLATFORM=github`）に関わる変更はしない（`@octokit/rest` を `packageRules` に載せるのは依存名の整合なので対象）

## 解くべき論点
なし

## やること

1. `.gitlab-ci.yml` の renovate ジョブの image を `renovate/renovate:44` に固定（メジャーバージョン 44 で確認済み。出典: GitHub renovatebot/renovate releases - 最新 44.119.1）
2. `.renovaterc.json` の runtime dependencies グループから `js-yaml` を削除し、代わりに実装の `yaml` を追加、さらに `@octokit/rest` を追加
3. `docs/architecture.md` の「その他」節の Renovate 記述を、ジョブが現在動作する状態に更新
4. `pnpm check` で検証

## 完了条件
- `renovate` ジョブの image がメジャー以上を固定したタグ（またはダイジェスト）になっている
- `.renovaterc.json` の runtime dependencies のグループが `package.json` の `dependencies` と一致している
- `docs/architecture.md`「既知の制約・注意点 > その他」の Renovate の記述と矛盾しない
- `pnpm check` が通る

## 結果

- 検証コマンド: pnpm check 579 pass / 0 fail（±0）。Docker Hub で `renovate/renovate:44` の実在を確認
- 受け入れで直したこと: 委譲先が `docs/architecture.md` の「schedule 未作成で `renovate` ジョブは一度も動いていない」を消し、依存名の一覧を書き写していたため、元の記述に戻した（事実は今も同じで、一覧は `.renovaterc.json` と二重になる）
- 振り返り: 兆候あり（受け入れでの直し）だが、タスク本文の完了条件が「矛盾しない」を求めたのを「書き換える」と読んだ一回きりのずれで、次の振る舞いを変えないので積まず
