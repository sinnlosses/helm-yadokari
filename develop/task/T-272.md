## 目的・背景
設定ユニットの `config.yaml` を、よく触る値（`helm.branchRef`・`apps[].branchToSync`）の `versions.yaml` と、あまり触らない値（`helm.locations[]`・`apps[].locations[]`）の `locations.yaml` に分ける。そのための仕様を先に正典へ書く。

いまは `docs/architecture/adr/0027-config-split-by-scope.md` が「変更頻度では分けない」と決めている。理由の一番目は、分けると `projectId` と `projectName` を両方のファイルに重複して書くことだった。今回は設定ユニット側で app を `projectName` をキーにしたマップで参照し、`projectId` は `registry.yaml` の `appSpecs[]` にだけ書く。こうすると重複が無くなるので、0027 を覆す。

形（ユーザーと合意済み）:

```yaml
# versions.yaml
branchRef: release/2026-q1
branchToSync:
  my-app: develop
  another-app: main
```

```yaml
# locations.yaml
helm:
  - valuesPath: charts/my-tenant/client-a/values.yaml
    anchor: clientATargetBranch
apps:
  my-app:
    - valuesPath: charts/my-tenant/client-a/values.yaml
      anchor: myAppVersion
```

## 決まっていること（蒸し返さない）
- `projectId` と `projectName` は `registry.yaml` の `appSpecs[]` にだけ書く。設定ユニット側は `projectName` をキーにして参照する
- `projectName` は参照の鍵になるので、同じ `registry.yaml` の中で一意でなければ設定エラーにする
- 設定ユニットは「`versions.yaml` と `locations.yaml` が両方あるディレクトリ」とする。片方だけなら設定エラーにする
- 2ファイルの app 名のキー集合が一致し、各キーが `appSpecs[]` にあることを検証する。要らなくなる検証（同じ `projectId` の重複、`projectId` と `projectName` の食い違い）は外す
- 0027 は新しい ADR で置き換える（0027 自体は消さず、置き換えられた旨を書く）
