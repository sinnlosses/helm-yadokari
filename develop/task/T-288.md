## 目的・背景
ユーザーの指示（2026-10-01）で、コードとYAMLの名前が合っていないところは、コードをYAMLに合わせる。いまは YAML → コードの詰め替えのたびに名前が変わっている。ADR 0035 の対応表に従い、次のとおり改名する。

- `ChartRepoConfig` → `ChartConfig`、`ConfigUnit.chartRepo` → `ConfigUnit.chart`
- `AppSpecSchema`/`AppSpec` → `RegistryAppSchema`/`RegistryApp`
- `ConfigUnit.groupId`/`groupName` → `ConfigUnit.group: GroupConfig`（新しい型。`src/domain/types.ts` に置き、`readonly id: GroupId`・`readonly name: GroupName`）
- `AnchorLocation.anchorName` → `AnchorLocation.anchor`（`AnchorLocationSchema` の外側の `.transform()` は詰め替えが要らなくなるので外す）
- `AppConfig.imageTagLocations` → `AppConfig.locations`

改名したフィールドを受ける作業用の型・変数（`ChartRepoScope` の `groupId`/`groupName` → `group`、`appSpecByName` → `registryAppByName`、変数・引数の `appSpecs`/`appSpec` → `registryApps`/`registryApp`）も追随させる。表に無い改名はしない。据え置くものは ADR 0035 の「改名しないもの」。

型の定義は `src/domain/types.ts` と `src/lib/config/schema.ts` にあり、利用箇所は `src/`・`test/`・`scripts/` に広がっている（`git grep -w` で洗う）。

## 決まっていること（蒸し返さない）
- 新しい名前は T-286 のADR（`docs/architecture/adr/0035-*.md`）の対応表に従う。表に無い改名はしない
- 挙動は変えない（純粋な改名）
