## 背景

`docs/coding-standards.md` の `## 関数の並び順` と CLAUDE.md の規約一覧に、「関数はファイル内で『外から使うもの → その内部で使うもの』の順に並べる」というルールがある。いまは人のレビューでしか守られておらず、機械的に検出されない。

lint は oxlint（`.oxlintrc.json`、`plugins: ["typescript"]`、`categories` は correctness=error / suspicious=warn、`devDependencies` は `oxlint ^1.67.0`）。`pnpm lint` は `oxlint src scripts test` に加えて `scripts/lint/validate-config.ts` を呼ぶ構成になっている。

## 決まっていること（蒸し返さない）

- oxlint の**既製ルールで縛れなかった場合は見送る**。`scripts/lint/` に自作の検査スクリプトを足すことはしない
- 見送る場合、`docs/coding-standards.md` の `## 関数の並び順` 節と CLAUDE.md の該当ルールは**そのまま残す**
- 導入できた場合は、`docs/coding-standards.md` の `## 関数の並び順` 節を削る（ルールが機械で守られるなら文章で二重に持たない）

## 解くべき論点

- oxlint にモジュールのトップレベル関数宣言の並び順を見るルールがあるか。`typescript/member-ordering` 系はクラスメンバ向けで、トップレベル関数には効かない見込みが高い
- 既製ルールが見つかっても、「`export` されたものを上に、そこからしか呼ばれない非公開関数を下に、非公開関数同士は呼ばれる順に」という本リポジトリの規約と**意味が一致しているか**。近いだけで意味が違うなら採用しない（部分的にしか守れないルールを入れると、通っていることが規約を満たす根拠にならなくなる）
- 採用する場合、既存コードの違反件数と、機械的に直せるか

## やること

1. 使用中の oxlint のルール一覧から候補を探す（`npx oxlint --rules` などで一覧を出し、`order` / `sort` / `member` といった語で絞る）
2. 候補があれば `.oxlintrc.json` で有効にして `pnpm lint` を走らせ、違反を確認して直す
3. 導入できたら、`docs/coding-standards.md` の `## 関数の並び順` 節と「### 節の索引」の該当行、CLAUDE.md「コーディング規約・レビュー方針」の該当ルールを削除する
4. **候補が見つからない／意味が一致しない場合は、何も導入せずに閉じる。** 見たルール名と却下理由を `evidence` に書き、`status: "done"` / `passes: false` にする

## 完了条件

導入した場合:

- `.oxlintrc.json` の `rules` に該当ルールが入っている
- `grep -c '^## 関数の並び順' docs/coding-standards.md` が `0` を返す
- `pnpm check` が通る

見送った場合:

- 追跡対象ファイルに変更が無い（`git status --porcelain` が `develop/` 以外について空）
- `evidence` に、確認した oxlint のルール名と、それぞれを却下した理由が書かれている

## 注意

- `## 関数の並び順` 節を消す場合も、その配下の `### テストのためだけの `export` はしない` は**別のルール**なので残し、独立した節に繰り上げる
- `.oxlintrc.json` の既存ルール（`typescript/consistent-type-imports` など）の設定は変えない

## 結果

見送り。oxlint 1.80.0 にモジュールレベルの関数の並び順を見るルールは無い: `typescript/member-ordering` は実測で `Rule 'member-ordering' not found in plugin 'typescript'`、唯一近い `no-use-before-define` は方向が逆で、規約どおり（export を上・helper を下）に並べた最小例が `'helper' was used before it was defined` で落ちることを実測した。`sort-keys` / `sort-imports` / `import/order` / `adjacent-overload-signatures` は対象が別。「決まっていること」に従い自作チェックは足さず、コード・ドキュメントとも無変更（`git status --porcelain` に対象ファイル無し）。
