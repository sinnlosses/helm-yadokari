## 背景

`docs/coding-standards.md` の `### JSDocのブロックタグは使わない` 小節が、`@param` / `@returns` / `@throws` / `@remarks` を「導入しない」と禁じている。理由として「全編が日本語の散文で書かれておりブロックタグの使用は0件、読者もチーム内限定でドキュメント生成器も使っていない」を挙げ、`docs/research/comment-conventions.md` を根拠として参照している。

ユーザーの方針変更により、**禁止をやめて「必要なら書いてよい」に改める**。

この小節は `docs/coding-standards.md` 側にしかない。CLAUDE.md の規約一覧にはブロックタグへの言及が無いので、CLAUDE.md 側の追随は不要（確認はすること）。`docs/coding-standards.md` の `### 1行目は要約、空けてから詳細` にも「（ブロックタグだけを採らなかった）」という一節がある。

## 決まっていること（蒸し返さない）

- 禁止規約は廃止する。ブロックタグは「必要なら書いてよい」扱いにする
- 積極的に推奨するところまでは行かない（既存コードにブロックタグを足して回るタスクではない）

## 解くべき論点

- 小節を丸ごと消すか、「必要なら書いてよい」と書き換えて残すか。**規約として言うことが残るなら残し、残らないなら消す**という基準で決める
- `docs/research/comment-conventions.md` は当時の調査記録（CLAUDE.md いわく「一次情報の出典と、採らなかった案」）なので**書き換えない**。ただし `docs/coding-standards.md` から「根拠と検討の詳細は…」というリンクが残る場合、いまの方針と食い違って読めないかを確かめ、必要なら参照の文言だけ直す

## やること

1. `docs/coding-standards.md` の `### JSDocのブロックタグは使わない` 小節を、上の論点にしたがって削除または書き換える
2. 「### 節の索引」の表の該当行を、残した/消した結果に合わせて直す
3. `### 1行目は要約、空けてから詳細` の「（ブロックタグだけを採らなかった）」という括弧書きが方針と食い違うので直す
4. `grep -rn 'ブロックタグ' docs/ CLAUDE.md README.md` で `docs/history/` と `docs/research/` 以外に取り残しが無いか確かめる
5. `pnpm format` をかけてから `pnpm check` を通す

## 完了条件

- `grep -c '^### JSDocのブロックタグは使わない' docs/coding-standards.md` が `0` を返す（見出し名が禁止を宣言しているので、書き換えて残す場合も見出しは変える）
- `grep -rn 'ブロックタグ' docs/coding-standards.md CLAUDE.md README.md` の結果に、ブロックタグを禁止・不採用とする記述が1件も無い
- 「### 節の索引」の表の行が、ファイル中の `##`/`###` 見出し（`## このファイルの読み方` とその小節を除く）と過不足なく対応している
- `pnpm check` が通る

## 注意

- `docs/research/comment-conventions.md` は当時の調査記録なので書き換えない
- `src/` のコメントには触らない（既存コードにブロックタグを足すタスクではない）
