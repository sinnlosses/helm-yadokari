## 目的・背景
前段 T-272 で正典に書いた2ファイルの形式に、CLI の読み込みと `config/`・`config.example/` を合わせる。

いまの実体:
- `src/lib/config/schema.ts`: `CONFIG_YAML_FILE_NAME`・`ConfigYamlSchema`（`helm` と `apps[]`）・`AppSchema`（`projectId`・`projectName`・`branchToSync`・`locations`）
- `src/lib/config/find-config-units.ts`: `config.yaml` の有無で設定ユニットを判定する（`collectUnitSegments()` とエラーメッセージ）
- `src/lib/config/load-config-unit.ts`: `buildConfigUnit()` が `config.yaml` を読み、`resolveProjectLinkage()` が `projectId` で `appSpecs[]` と結合し、`projectName` の食い違いを検証する
- `src/lib/config/validate.ts`: `validateNoDuplicateProjectIds()`（`registry.yaml` と `config.yaml` の両方に使っている）

変える向き（4.4節に沿って）: `validateNoDuplicateProjectIds()` は `registry.yaml` の `appSpecs[]` にだけ使う（同じ `projectId` の重複は引き続き設定エラー）。`resolveProjectLinkage()` は `projectName` で `appSpecs[]` を引く形にし、食い違いの検証を外す

## やること
前提の確認結果: 目的・背景の記述（ファイル・関数名）は実物と一致している。実装は下の順で進める。

### 1. スキーマ（`src/lib/config/schema.ts`）
- `CONFIG_YAML_FILE_NAME`・`ConfigYamlSchema`・`AppSchema`（型 `ConfigApp`）・`HelmSchema`（型 `ConfigHelm`）を削除し、次を足す。
  - `VERSIONS_YAML_FILE_NAME = "versions.yaml"`・`LOCATIONS_YAML_FILE_NAME = "locations.yaml"`
  - `VersionsYamlSchema`: `branchRef`（必須・非空・`toBranchName`。欠落時のメッセージは versions.yaml の書き方を案内する文言に直す）と `branchToSync`（`z.record`: キー=非空の app 名を `toProjectName`、値=非空の `toBranchName`）
  - `LocationsYamlSchema`: `helm`（`AnchorLocationSchema` の配列・1件以上・必須。欠落時のメッセージは locations.yaml 向けに直す）と `apps`（キー=`toProjectName`、値=`AnchorLocationSchema` の1件以上の配列のレコード）。`apps: {}` は空を許す（従来の `apps: []` と同じ）
  - 型は `ConfigHelm` の代わりに必要な形だけ export（`load-config-unit.ts` が使うもの）。`AppSpec` はそのまま
- `AppSpecSchema` の doc コメントから「`config.yaml` 側と結合・`projectName` は食い違い検証用」の記述を消し、「設定ユニット側が `projectName` で引く台帳」に直す。ファイル先頭コメント（「2ファイル」）も3種に直す。

### 2. 走査（`src/lib/config/find-config-units.ts`）
- `collectUnitSegments()` は、ディレクトリごとに `versions.yaml`・`locations.yaml` の有無を見る。両方あれば設定ユニット、片方だけならそのパスを含むメッセージで例外（片方だけのディレクトリは設定エラー）、どちらも無ければ何もしない。降りる範囲は今と同じ（打ち切らない）
- 深さ0・深さ3以上・入れ子のエラーメッセージの `CONFIG_YAML_FILE_NAME` を、両ファイルを指す文言に直す（深さ0は「`versions.yaml`/`locations.yaml` が `registry.yaml` と同じ階層にあります」）。深さ0の判定は片方だけの検出より後でも先でもよいが、片方だけ判定を先にする
- 関数コメントの「`config.yaml` を持つディレクトリ」を直す
- `limit-to-target.ts` の 53・75 行付近のメッセージも同様に直す（`CONFIG_YAML_FILE_NAME` の import 差し替え）

### 3. 読み込み・結合（`src/lib/config/load-config-unit.ts`）
- `loadConfigUnits()` は `configYamlPath` の代わりに `versionsYamlPath`・`locationsYamlPath` を `ConfigUnitScope` に持たせる
- `buildConfigUnit()` で両方を `parseYamlFile` する。順に検証する:
  1. `branchToSync` と `apps` のキー集合が一致しなければ例外（どちらにだけ無いかを名前で示す）
  2. `resolveProjectLinkage()` を、app 名（`projectName`）で `appSpecs[]` を引く形に変更。`ChartRepoScope` に `projectName → AppSpec` の `ReadonlyMap` を持たせ、`loadConfigUnits()` で1回だけ作る。無ければ例外（`registry.yaml` に見つからない旨。どちらのファイルの名前かも書く）。`projectName` の食い違い検証は削除
  3. `validateNoDuplicateLocations()` は `locations.yaml` の `apps`（ラベルは app 名）と `helm[]` を渡す。ファイルパスは `locationsYamlPath`
- `AppConfig` は `projectId`・`tagFormat` を引いた `AppSpec` から、`branchToSync` を versions から、`imageTagLocations` を locations から作る。app の並び順は `branchToSync` のキー順にそろえる
- `resolveHelmConfig()` はファイルパス引数を `locationsYamlPath` にし、メッセージの `helm.locations[]` を `locations.yaml の helm[]` に直す（`ConfigUnit.helm` の形は変えない）。ドメイン型（`src/domain/types.ts` の `AppConfig`/`HelmConfig`）は形を変えず、コメント中の `config.yaml` だけ「versions.yaml / locations.yaml」に直す

### 4. 検証（`src/lib/config/validate.ts`）
- `validateNoDuplicateProjectIds()` は `registry.yaml` の `appSpecs[]` にだけ使う（呼び出しは `loadConfigUnits()` の1箇所のみになる）。あわせて `validateNoDuplicateProjectNames()`（同じ `registry.yaml` の `projectName` 重複を設定エラーにする。メッセージに `filePath` と重複した名前）を新設し、同じ場所から呼ぶ。`validateNoDuplicateProjectIds()` の doc コメント（「2ファイルを突き合わせるため」）は台帳内の重複という理由に直す。冒頭コメントの `config.yaml` も直す
