## 目的・背景
ユーザーの指示（2026-10-01）で、`config/` のYAMLキーを次のとおり改名する。2ファイルで同じ対象を指すキーを揃え、対になる塊の名前の形と、親の名前を繰り返す子キーを直すため。

- versions.yaml: `helmBranchRef` → `helm`、`appBranchToSync` → `apps`（locations.yaml の `helm` / `apps` と同じキーにして、値と書き込み先の区別はファイルで表す）
- registry.yaml: `chartToUpdate` → `chart`、`appSpecs` → `apps`、`group.groupId` → `group.id`、`group.groupName` → `group.name`

スキーマは `src/lib/config/schema.ts`（`RegistryYamlSchema`・`VersionsYamlSchema`・`GroupSchema` と、キー名を含むエラーメッセージ）。キー名は `config/`・`config.example/`・テスト・`scripts/lint/remote-existence/`・`scripts/smoke/`・`.claude/skills/register-chart/SKILL.md`・`docs/requirements.md` 4.4節・`docs/glossary.md`・`README.md`・`docs/smoke-test.md` などにも現れる（`git grep -w` で洗う）。

スキーマの出力のキーも変わるので、`src/lib/config/load-config-unit.ts` の受け取り側（`chartToUpdate: chart` の分解代入・`versions.helmBranchRef`・`versions.appBranchToSync`・`group.groupId`/`group.groupName`）と、YAMLを文字列で組むテスト・`scripts/smoke/group-fixture-content.ts` もこのタスクで追随させる。`src/domain/types.ts` の型・フィールドは変えない。

## 決まっていること（蒸し返さない）
- 改名先は上の6つ（ユーザー指示）。旧キーの互換読み込みは設けない（知らないキーは設定エラーのまま）
- このタスクではYAMLのキーと、キー名を書いた文言（エラーメッセージ・コメント・docs）だけを変える。コードの型名・フィールド名の改名は後段のタスクで行う

## 解くべき論点
なし

## やること

前提の確認結果: 目的・背景の主張（`schema.ts`・`load-config-unit.ts` の該当箇所、`scripts/smoke/group-fixture-content.ts`、各docsにキー名が現れること）は実物と一致した。作業ツリーはクリーン。旧キーは `config/`（2チャート分）・`config.example/` にもある。

手順（各段のあと `git grep -wn` で旧キーの残りを確かめる）:

1. スキーマと読み込み（`src/lib/config/` ほか）
   - `src/lib/config/schema.ts`: `RegistryYamlSchema` のキーを `chartToUpdate`→`chart`、`appSpecs`→`apps`（値は `AppSpecSchema` のまま）に。`GroupSchema` のキーを `groupId`→`id`、`groupName`→`name`（値は `GroupIdSchema`/`GroupNameSchema` のまま）に。`VersionsYamlSchema` のキーを `helmBranchRef`→`helm`、`appBranchToSync`→`apps` に。キー名を含むエラーメッセージ・コメントも追随する（`group.groupId は必須です`→`group.id`、`group.groupName`→`group.name`、`groupId（数値ID）と groupName（フルパス）`→`id`/`name`、`helmBranchRef は必須です`/`…は空にできません`→`helm`、`appBranchToSync は空にできません`→`apps`、`LocationsYamlSchema` の `versions.yaml の helmBranchRef とセット`→`helm`、`appMapSchema` のコメントと tagFormat のエラーメッセージの `appSpecs[]`→`apps[]`）。`helm`/`apps` は2ファイルにあるキーなので、メッセージには `registry.yaml の apps[]`・`versions.yaml の helm` のようにファイル名を添える
   - `src/lib/config/load-config-unit.ts`: 分解代入を `chart, apps: appSpecs, accessTokenEnv, group` に（`chartToUpdate: chart` は `chart` だけに）。`group.groupId`→`group.id`、`group.groupName`→`group.name`、`versions.appBranchToSync`→`versions.apps`、`versions.helmBranchRef`→`versions.helm`。エラーメッセージ・docコメント（`registry.yaml の appSpecs[]`→`apps[]`、`validateSameAppNames` のメッセージ `versions.yaml の apps と locations.yaml の apps で…`）も追随。`ChartRepoScope` の `groupId`/`groupName`・`appSpecByName`・`ConfigUnit` のフィールドは T-288 の担当なので変えない
   - `src/lib/config/validate.ts`・`src/domain/brand.ts`・`src/domain/tag-format.ts`・`src/domain/types.ts`・`src/steps/resolve-tags/sub-steps/resolve-latest-tag.ts`: コメント中のYAMLキー名（`group.groupId`・`group.groupName`・`appSpecs[].tagFormat`・`helmBranchRef`・`appBranchToSync`）だけ新キーに直す。`brand.ts` のエラーメッセージ（`group.groupId は…`、`toGroupPath(s, "group.groupName")`）も `group.id`/`group.name` に。型・フィールド・引数名は触らない

2. スクリプト
   - `scripts/smoke/group-fixture-content.ts`: 組み立てるYAMLの `groupId:`/`groupName:`→`id:`/`name:`、`chartToUpdate:`→`chart:`、`appSpecs:`→`apps:`、`helmBranchRef:`→`helm:`、`appBranchToSync:`→`apps:`（引数名 `groupId` は変えない）
   - `scripts/lint/remote-existence/remote-existence.ts`: ユーザーに出すメッセージ・コメント中のYAMLキー名のみ（`group.groupId`→`group.id`、`group.groupName`→`group.name`、`appBranchToSync`→`versions.yaml の apps`、`helmBranchRef`→`versions.yaml の helm`）。`ValidateContext.groupId`・引数名・`remote-cache.ts`・`provision-group.ts` は ADR 0035 の「改名しないもの」なので触らない

3. `config/`・`config.example/` のYAML（キー名だけ。ID・名前・ブランチ値は変えない）
   - `registry.yaml` 3ファイル（`config/yadokari-smoke-test-chart`・`config/yadokari-smoke-test-chart2`・`config.example/my-team-chart`）: `group.groupId/groupName`→`id/name`、`chartToUpdate`→`chart`、`appSpecs`→`apps`
   - `versions.yaml`（`git grep -lw 'helmBranchRef' -- config config.example` で列挙。config/ 4件・config.example/ 2件）: `helmBranchRef`→`helm`、`appBranchToSync`→`apps`。ファイル内コメントの旧キー名も直す
   - `config.example/my-team-chart/my-unit/locations.yaml`・`config.example/README.md`・`config/README.md` のコメント中の旧キー名

4. テスト（YAML文字列・期待文言に旧キーを書いているもの）
   - `test/lib/config/fixture.ts`（YAMLを組む関数。出力するYAMLのキーを `helm:` 等に。入力オブジェクトのプロパティ名 `helmBranchRef?` は後述）、`test/lib/config/{config,schema,validate}.test.ts`、`test/main.e2e.test.ts`、`test/helpers.ts`、`test/scripts/lint/remote-existence/remote-existence.test.ts`（メッセージ期待文言）、`test/scripts/smoke/group-fixture-content.test.ts`（期待YAML全文とテスト名）
   - 旧キーが設定エラーになることは `schema.test.ts` の既存の未知キー検証で足りるか確認し、足りなければ1件足す（互換読み込みは設けない）

5. ドキュメント
   - `docs/requirements.md` 4.4節（YAML実例と本文。sed の終端は `^#\{2,4\}`）と他の節の旧キー言及、`README.md`（「設定」章のYAML例と本文。L45・60・232-246・262-286・400-404）、`docs/smoke-test.md`、`docs/architecture.md` L150、`.claude/skills/register-chart/SKILL.md`（14箇所）
   - `docs/glossary.md`: 見出し「chartToUpdate・appSpecs」→「chart・apps（registry.yaml）」、「グループ（group・groupId・groupName）」→「グループ（group・id・name）」にし、本文の英語識別子・各項の言及と、冒頭「用語の索引」の表（L30・L34）を追随。`helmBranchRef`・`appBranchToSync` の各項（L118-143・L178-181）はキー名を `helm`・`apps`（versions.yaml）に直し、旧キーの理由づけ（「`helmBranchRef`という名前にしている理由」「YAMLキーとコードのフィールド名が違う理由」）は成り立たなくなるので、ADR 0035 の規則Bへの参照に書き換える。該当項目の「表記ゆれ」に「2026-10-01: versions.yaml `helmBranchRef`→`helm`・`appBranchToSync`→`apps`、registry.yaml `chartToUpdate`→`chart`・`appSpecs`→`apps`・`group.groupId`→`group.id`・`group.groupName`→`group.name`」を記録する（旧キー名はこの記録にだけ残す）
   - `docs/architecture/adr/0023・0027・0033・0034` と `docs/research/github-support.md` は経緯の記述なので書き換えない。`docs/history/` も触らない。`.renovaterc.json` の `groupName` はRenovateの設定キーで無関係

6. 検証: 完了条件の `git grep -wn` が許容範囲だけになること、`pnpm lint:validate-config`（`config/`・`config.example/` の両方）、`pnpm check`

完了条件との食い違い（着手時に確認が要る点）:
- TypeScript識別子の `helmBranchRef` が、完了条件の許容リスト（ADR 0035 の対応表）に無いのに `src/steps/apply-updates/sub-steps/shared/types.ts`（`MrEntries.helmBranchRef`）・`collect-mr-entries.ts`（引数・戻り値）・`build-mr-content.ts`、対応するテスト3件（`apply-updates.test.ts`・`build-mr-content.test.ts`・`collect-mr-entries.test.ts`）、`test/lib/config/fixture.ts` の入力プロパティ `helmBranchRef?` に残る。これらはYAMLキーの写しではなくMR本文用のTS識別子で、「型名・フィールド名の改名は後段」の決定どおり変えない。完了条件の grep はこの分だけヒットが残るので、結果に「許容として残した」と明記する（許容リストへの追記は指示者の判断）

## 完了条件
- `git grep -wn 'helmBranchRef\|appBranchToSync\|chartToUpdate\|appSpecs'` が、`docs/history/` と glossary の「表記ゆれ」の記録・ADRの経緯の記述以外でヒットしない。`group` の子キー `groupId`/`groupName` も同様。ヒットが残ってよいのは、ADR 0035 の対応表で T-288 が改名するTypeScriptの識別子（`AppSpec`・`AppSpecSchema`・`appSpecByName`・変数/引数の `appSpecs`/`appSpec`、フィールドの `groupId`/`groupName`）と、ADR 0035 が「改名しないもの」に挙げた `groupId`/`groupName`（`scripts/smoke/provision-group.ts`・`ValidateContext` など）だけ
