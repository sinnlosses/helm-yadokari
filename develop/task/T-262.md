## 背景

`docs/coding-standards.md` には、規約とその理由のほかに「このリポジトリで実際にどう対応したか」という記録が混ざっている。CLAUDE.md は同ファイルを「ルール本体は CLAUDE.md 側が正典で、ここにはその理由と例外だけを書く」と位置づけており、対応記録はその役割の外にある。

該当しそうな箇所（T-259 で行番号がずれるので見出しで示す）:

- `### 消すかどうか`: 「**個別の判断（実施済み）**」「**`src/utils/` の単体テストの整理（実施済み）**。全36テストファイルを1つずつ除外して…」「**敵対的に検討したうえで残したもの**」「**残り32ファイルの中身の精査（実施済み）**」
- `### 足すかどうか`: 「埋めないと決めた3件」
- `## `async`/`await` と `.then()`/`.catch()``: 「採らなかった立場:」以下
- 「### 節の索引」の表のうち、上記を指す説明文（`実施済みの個別判断` / `埋めないと決めた3件` / `全面禁止を採らなかった理由`）

`### 消すかどうか` と `### 足すかどうか` はこの記録でファイルの分量の大半（500行台〜620行台）を占めている。

## 決まっていること（蒸し返さない）

- 落とすのは「こう対応した」という**記録だけ**。ルールの**理由と例外は残す**（CLAUDE.md との役割分担「ルール本体=CLAUDE.md / 理由と例外=coding-standards.md」は変えない）
- 落とした記録は**どこにも退避せず削除する**。git 履歴に残るので `docs/history/` に新しいファイルは作らない

## 解くべき論点

- 「採らなかった立場」「敵対的に検討したうえで残したもの」のように、**理由の説明と対応記録の中間にあるもの**をどちらに倒すか。判定は「この文が無いと規約の意味（何をしてよくて何が駄目か）が変わるか」で行い、変わらないなら落とす
- 記録を落としたあと `### 消すかどうか` `### 足すかどうか` が規約として成立するか。判定の基準だけが残って読める状態にならないなら、基準を書き足してから落とす
- `docs/history/test-inventory.md` や `docs/architecture.md` など他ファイルが、削除対象の記述を参照していないか

## やること

1. 上記の該当箇所を精査し、論点の基準にしたがって落とす
2. 「### 節の索引」の表の説明文を、残った中身に合わせて直す
3. `grep -rn 'coding-standards' docs/ CLAUDE.md README.md .claude/` で、削除した節を指す参照が残っていないか確かめ、あれば直す
4. `pnpm format` をかけてから `pnpm check` を通す

## 完了条件

- `grep -n '実施済み\|敵対的に検討\|埋めないと決めた\|採らなかった立場' docs/coding-standards.md` が何も返さない
- 「### 節の索引」の表の各行が、ファイル中の `##`/`###` 見出し（`## このファイルの読み方` とその小節を除く）と過不足なく1対1で対応している
- `sed -n '/^### 消すかどうか/,/^#\{2,4\} /p' docs/coding-standards.md` と `### 足すかどうか` の出力に、テストを消す/足すの**判定基準**が残っている（空の節になっていない）
- `docs/` と CLAUDE.md と README.md に、削除した節を指す参照が残っていない
- `pnpm check` が通る

- CLAUDE.md のルール一覧は削らない（ルール本体の正典は CLAUDE.md 側）
