## やること
前提の確認: `src/main.ts` の39行目 `logger.info({ event: "summary", ...processed.counts })` が件数だけを出していること、`RunProcessResult` が `reports: readonly ConfigUnitReport[]`（`chartDirName` / `unitPath` / `chartProjectName` / `result` / `reason` を持つ）を既に返していることを確認済み。型の追加は要らない。

1. `src/main.ts` を直す（完了条件1）
   - `run()` の summary 行を `logger.info({ event: "summary", ...processed.counts, failedUnits: listFailedUnits(processed.reports) })` にする。キー名は `failedUnits`。
   - ファイル末尾（`summarizeResults` の後ろ）に `listFailedUnits(reports)` を足す。`result === "ERROR"` のレポートだけを `{ chartDirName, chartProjectName, unitPath, reason }` に写して readonly 配列で返す（ジョブログの末尾だけで失敗の中身まで追えるよう `reason` も載せる。ERROR が無ければ `[]`）。`as` キャストは使わず、`filter` ではなく `flatMap` で絞る。順序は `reports` の並びのまま。
   - `RunProcessResult` の doc コメントの「`counts`は`summary`ログに出す…」は今のままで正しい（`failedUnits` は `reports` から `run()` が作る旨だけ1行足すか、変えない）。
   - 終了コード（`counts.ERROR === 0`）は触らない。
2. テストを直す（完了条件1）。`test/main.test.ts` の `summaryCounts()` は CREATED/SKIPPED/ERROR の3キーだけを取り出すので、`failedUnits` を足しても既存アサーションは壊れない。
   - `test/main.test.ts` 195行付近の「一部のトークンが 401 → CREATED:1 / ERROR:1」のテストに、`summary` の `failedUnits` が `[{ chartDirName: "teamB-chart", chartProjectName: "teamB-chart", unitPath: <chartB の unitPath>, reason: <ERROR の reason> }]` になる検証を足す（`summaryCounts` と並べて `summaryFailedUnits()` ヘルパーを足すか、`logger.info` の呼び出しから `summary` を引く共通ヘルパーに寄せる）。chartB の unitPath は同テスト内のフィクスチャから取る。
   - 同ファイル 217行付近「run_start / summary / run_end イベントをログ出力する」の `objectContaining` に `failedUnits: []` を足し、ERROR が無いとき空であることを確かめる。
   - `test/main.dry-run.test.ts` 131行付近（SKIPPED:1）と `test/main.e2e.test.ts` は `objectContaining` / summary 非参照のため変更不要（e2e は grep で `summary` を見ていないことを確認済み）。
3. ドキュメントの追随（完了条件2）
   - `README.md` 154行の「実行ログの例」の summary 行に `"failedUnits":[]` を足す。ERROR が出た実行では `failedUnits` に `{chartDirName, chartProjectName, unitPath, reason}` の配列が入ることを、同節の説明文（致命的エラーの説明の前あたり）に1〜2文で書く。
   - `docs/smoke-test.md` 415行（パス3: 部分失敗）の `summary` の記述に「`failedUnits` に `tenant2/client2` が1件載る」を1行足す。ほかのパス（385・410・424・435行）は `failedUnits` が空なので変えない。
   - `docs/requirements.md` は要件の文言を変えない決めなので触らない。`docs/architecture.md` / `docs/glossary.md` に `summary` ログの項目説明は無いことを grep で確認済み（変更なし）。
